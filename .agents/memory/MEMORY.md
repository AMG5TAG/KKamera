- [Expo web module crashes](expo-web-module-crashes.md) — Top-level `import` of native-only Expo modules (e.g. `expo-local-authentication`, `expo-sensors`) can crash the web bundle because of missing transitive deps (e.g. `invariant`). Fix: `await import("module")` inside platform-guarded functions so Metro never bundles/evaluates the module on web.
- [Pnpm workspace + Metro stale hash bug](pnpm-metro-stale-hash.md) — In pnpm monorepos, `@expo/cli` auto-detects the workspace root and uses it as `server.unstable_serverRoot`, causing entry point paths to embed full pnpm hash directories (e.g. `node_modules/.pnpm/expo-router@6.0.24_@types+..._162db9813.../node_modules/expo-router/entry`). When deps change, the hash changes but browser HMR reconnections still send the old hash path, causing `UnableToResolveError`.
- [API server startup ordering — listen before migrations](api-server-startup-ordering.md) — app.listen() must come before await runAppMigrations(); slow prod DB cold-start causes port timeout and silent deployment failure.
